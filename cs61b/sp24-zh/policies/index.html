课程信息

本文件概述了加州大学伯克利分校教授的本课程的政策。

基本背景信息

这些课程政策很长。除了合作政策之外，我们并不期望你一次性阅读全部内容。但是，希望你能在本文档的某个地方找到任何后勤问题的答案。

欢迎来到 计算机科学 61B

CS 61 系列是计算机科学的入门课程，特别强调从程序员的角度看软件和机器。CS 61A 涵盖了高级的问题解决方法，为你提供了多种组织编程问题解决方案的方式，包括函数的组合、 对象的集合或规则的集合。在 CS 61B 中，我们转向更详细（从某种程度上说，更基础） 的编程层次，特别关注编写程序的设计和运行程序的效率。

先修要求

本课程假设你已经学过 CS 61A、CS 88 或 E7，或具有修过这些课程之一的同等背景知识。本课程 在很大程度上建立在你已经修过 CS 61A 的假设之上。CS 88 和 E7 的学生可能会发现 课程开始时有些吃力，特别是在面向对象编程方面。我们假设你入学时没有 Java 经验， 但我们将很快掌握基本 Java 语法。

如果你已有 Java 经验，很好！我们希望你能帮助 其他同学完成讨论、实验和我们的课程论坛，特别是在 开始几周大家都在学习 Java 的时候。

替代课程

这是一门关于数据结构和编程方法的课程。由于不使用语言很难教授编程， 因此这门课恰好也教 Java。但是，这并不是一门关于 Java 的详尽课程， 也不是关于创建 Android 应用程序、用户界面、图形或任何有趣内容的课程。

你们中的一些人可能已经修过数据结构课程，只是想学习 Java 或 C++。对你来说， 自学可能是更好的选择。

最后，1 学分的自学课程 CS 47B 面向"在 61B 中有足够部分学分"的学生， 允许他们（在导师许可的情况下）完成 CS 61B 课程要求而不必参加完整课程。47B 指南在 此链接 。

心理健康与健康

作为一名学生，你可能会遇到各种可能造成学习障碍的问题，例如人际关系紧张、焦虑加剧、酗酒/吸毒问题、抑郁、注意力难以集中和/或缺乏动力。这些心理健康问题或压力事件可能导致学业表现下降或降低学生参与日常活动的能力。加州大学提供服务来帮助你解决这些以及你可能遇到的其他问题。如果你或你认识的人正遭受上述任何情况，请考虑利用校园内提供的保密心理健康服务。我们鼓励你联系咨询中心寻求支持。校园辅导员或下班后临床医生全天候 24/7 可用。

全国自杀预防生命线是一个 24 小时热线，任何学生或教职员工都可以拨打与人谈论自杀问题：(800) 273-TALK (8255)。

更多资源可以在我们的 资源标签页 中找到。

如果你正在经历影响心理健康的特殊情况，并希望与课程工作人员会面以制定课程内的特殊照顾安排，或者希望获得更多资源，你可以 在此处 与我们预约会议。

特殊照顾

加州大学伯克利分校致力于创建一个满足其多元化学生群体（包括残疾学生）需求的学习环境。如果你预计或在本课程中遇到任何学习障碍，请随时与讲师讨论你的关切。

如果你有残疾，或认为自己可能有残疾，你可以与残疾学生项目（DSP）合作申请官方特殊照顾。残疾学生项目（DSP）是负责与学生本人及其讲师合作批准与残疾相关的学术特殊照顾的校园办公室。你可以在此处找到有关 DSP 的更多信息，包括联系信息和申请流程。如果你已经通过 DSP 获得了特殊照顾批准，或正在走流程，请预约与课程工作人员会面，以便我们制定实施方案。

课程形式

讲座

讲座安排在周一、周三和周五下午 1 点至 2 点，地点为 Dwinelle 155。由于教室不够大，无法容纳所有注册学生亲自参加，讲座将通过 Zoom 同时进行网络直播。

我们将在内容日程上发布讲座录像以及 Josh Hug 的 2023 年春季网络视频。两者内容大致相同。

讨论课

讨论课为期 1 小时，内容包括复习上周学习材料的练习题。在讨论课上，助教将帮助学生复习材料并解答练习题中的问题。请注意，你的助教可能不会覆盖练习题的所有问题，这是有意的——你可以在之后通过我们发布的答案解析来复习剩余的题目。

讨论课将主要以线下形式进行，但我们可能会在 Zoom 上提供有限的远程选项。

有关每个 section 负责人员的信息可以在工作人员页面上找到。本学期我们不会进行 section 报名。

所有 section 和讲座的日程表可以在课程网站主页的底部找到。

讨论课出勤不是强制性的，但你会因出勤获得 进度积分 。

本学期我们有三 (3) 种不同类型的讨论课：

Bridge 复习课（2小时）

你希望在深入讨论练习题之前更加强调概念吗？如果是这样，我们的 bridge 讨论课可能适合你！我们一些优秀的助教将主持一个两小时的讨论课，专门为那些对本周材料不太熟悉的同学设计。这是一个很好的方式来更加熟悉主题，并在 section 期间获得更加个性化的关注。bridge 讨论课期间涵盖的材料和难度与 regular 讨论课相同，我们会延长迷你讲座来加强概念理解。

Regular (1小时)

这个 section 最适合已经跟上讲座进度并准备解决一些中等难度题目的同学。如果你不确定参加哪个，我们推荐参加这个 section。

考试难度（1小时）

Exam-level sections 是节奏更快的 section，包含更困难题目的不同练习题。这些 section 的目标是让你熟悉 exam 级别的问题和解决问题的策略。通常会更少地关注复习/迷你讲座，而将更多时间用于解题。

实验课

实验课为时 2 小时，包含学生提交计分的编程作业。在这些 section 中，助教将介绍作业、复习相关材料并回答学生的问题。

实验课将主要以线下形式进行，但我们可能会在 Zoom 上提供有限的远程选项。

实验课出勤不是强制的，但有一个例外——Project 3 Checkoffs。这个作业需要由助教检查通过才能获得学分。

有关每个 section 负责人员的信息可以在工作人员页面上找到。

本学期我们不会有 section 报名。对于强制出勤的实验课：

  • Project 3 Checkoffs：将有官方报名渠道，你和你的搭档将展示你们为 Project 3 完成的工作。报名将在课程最后一周前不久开放。

答疑时间

在答疑时间，你可以从我们的工作人员那里获得各种作业、考试准备、后勤事务以及你可能需要的任何建议方面的帮助。我们将同时提供线下和线上答疑时间。你也可以在实验课期间询问与实验无关的问题。

我们将通过 Zoom 进行答疑时间。要了解更多关于 CS 61B 答疑时间如何运作的信息，请阅读我们的 答疑时间指南 。我们将使用在线 答疑排队系统 来跟踪答疑时间的学生。工作人员将始终跳过排队中不遵守我们答疑时间政策的工单。

资源

网站

课程主页 将提供课程信息的一站式服务。课程日程以及所有讲义、作业、实验、常见问题等都将发布在那里。

讨论论坛

我们本学期的讨论论坛将使用 Ed Discussions。对于大多数关于课程的问题，Ed 是提问的正确地方。课程工作人员会定期阅读，所以你会很快得到答案。此外，通过在线发布而不是直接给我们发邮件，其他学生可以通过看到问题和答案而受益。在提问之前别忘了检查 Ed，以防其他人已经发布过了。如果你有关于自己代码的问题，不应该与班级分享，或者你有个人问题，你可以在 Ed 上发布私人帖子，只有讲师和工作人员才能看到。

请阅读我们的 Ed 指南 和 政策 。我们只会回复遵守我们 Ed 使用政策的问题。

工作人员邮箱

电子邮件地址 cs61b@berkeley.edu 将向课程工作人员（讲师和首席助教）发送消息。你可以用它来进行你不想在我们班级论坛上看到的通信。首席助教和讲师都会阅读它，所以你通常会在几天内收到回复。如果你发送的问题具有普遍意义，我们可能会在 Ed 上发布回复（当然，我们会保密个人信息）。如果你有任何需要例外于课程政策的问题（例如医疗紧急情况或导致长期缺勤的突然必要旅行），请联系 cs61b@berkeley.edu 。 请不要就例外事项给讲师或课程工作人员发电子邮件。请发送邮件至 cs61b@berkeley.edu 。

Beacon

我们将使用我们自己定制的学习管理系统 Beacon，而不是使用 bCourses，其网址为 beacon.datastructur.es 。你可以使用 Beacon 来跟踪你的成绩和迟交作业。你也可以 在此处 阅读我们关于 Beacon 的完整指南。

阅读材料

本课程没有指定的必修教材。

有一本由我自己和一大群课程工作人员编写的在线教材。可以在以下网址找到： https://cs61b-2.gitbook.io/cs61b-textbook/ 。 如果你觉得这些笔记不够，你可以考虑参考 Paul Hilfinger 的（免费）Java 参考手册 或 《Head First Java》第二版，作者 Sierra 和 Bates（O'Reilly，2005） 。 这些都不是课程必需的。课程第 5-14 周的 可选 教材是 Wayne 和 Sedgewick 编写的《算法》第四版。

Java 核心语言的官方描述可在以下网址在线获取： Java 语言规范 （Java SE 17 版），作者 James Gosling、Bill Joy、Guy Steele、Gilad Bracha、 Alex Buckley、Daniel Smith 和 Gavin Bierman。它非常全面和精确，但代价是内容相当密集和技术性强。你会发现官方的 Java 17 文档 也很有用

软件

本课程的官方编程环境和文本编辑器是名为 IntelliJ 的集成开发环境（IDE）。虽然我们不会强制使用 IntelliJ，但我们强烈推荐它。除了 IntelliJ，我们不会正式支持任何其他编辑或编程环境。

本学期，我们将使用 Java 17 或更高版本（因此至少需要 IntelliJ 2021.2.1，但我们推荐 IntelliJ 2022.3 或 IntelliJ 2023.2）。

你可以在任何 Windows、Mac OS X 或 Linux 电脑上做任何你想做的工作。你将在实验课 1 中设置你自己的电脑。

本学期我们将使用版本控制系统 Git ，并在 GitHub 上使用私有仓库。 版本控制系统允许你在开发的各个阶段维护一系列文件的"快照"。如果使用得当，这会为你提供一些备份保护，这样当出现问题时，你可以恢复工作的先前状态。此外，对于面向团队的项目（以及在现实世界中），版本控制系统有助于管理协作工作。

课程作业

本课程有五个必修方面可以让你获得分数：

  1. 每周调查
  2. 实验作业
  3. 家庭作业
  4. 项目
  5. 考试

每周调查

虽然讲座和 section 的出勤不是必需的，甚至也不是预期的，但我们确实希望你能跟上学习材料。为了帮助我们跟踪你的学习进度和对课程的感受，我们将有 12 个每周调查，截止时间为每周一晚上 11:59。

提交 10 个每周调查将获得满分（即你可以跳过 2 个）。提交更多不会获得额外学分。

实验作业

在课程的第一阶段（第 1 到第 5 周），实验课将帮助你设置电脑并教你如何使用基本的 Java 编程工具，在完成 Project 1 后还将包括同伴代码审查。

在课程的第二和第三阶段（第 6-15 周），实验课通常会涉及讲座中描述的某些数据结构或算法的实现。所有实验课的完成时间不应超过两小时，尽管有些可能会稍微长一点。你将使用 GitHub 以电子方式提交所有内容，你的成绩将在 Gradescope 上查看。

实验课根据 Gradescope 上的自动评分器测试进行评分。没有隐藏的测试让你看不到分数，尽管我们可能有你无法访问的测试。

在 14 个实验课中，只有 10 个需要你提交作业。这 10 个实验课每个价值 5 分（总共 50 分）。

你不需要参加实验课来获得实验课的学分，但有一个特定的作业除外（见上面的 实验课 部分）。

本学期，我们 不 允许实验作业有实验搭档。我们确实鼓励你讨论想法（参见 实验合作政策 ），但你提交的代码应该是你自己的。

没有实验课会被删除，但我们有宽松的迟到政策。

家庭作业

本课程有 5 个必修的家庭作业。

我们有三种类型的家庭作业：

  • 编程作业（HW0、HW2），与实验课类似。
  • HW1 是关于在 CS 课程中如何做一个好同学的作业。它旨在设定课程规范，并提醒我们如何在 CS 61B 中尊重和包容伯克利社区的所有成员。
  • 概念作业在第二次期中考试（HW3）和期末考试（HW4）前不久截止，帮助你备考。它们将在 Gradescope 上提供，包括选择题和填空题的组合。你可以预期需要在纸上解决这些问题，然后在 Gradescope 上填写答案。

作业 0、1、3 和 4 价值 15 分。作业 2 是更具挑战性、更耗时的作业，价值 30 分。

没有作业会被删除，尽管我们有宽松的迟到政策。

项目

除了作业和实验课之外，还将有 4 个编程项目。在这些项目中，你将构建一个完整的系统。除了 Project 3 之外，所有项目都必须独立完成。

Project 0 和 1 相对比 Project 2 和 3 容易，花费时间更少，并且有更多的框架代码。Project 2 将是一个更大规模的设计项目，只有很少的骨架代码。Project 3 将是一个顶点项目，你将从头开始设计一个项目。取决于你的雄心程度，它最终可能比 Project 2 的工作量大得多。

每个项目都有特定的主题：

  • 项目 0（2048）：Java 入门
  • Project 1（双端队列）：基础设计、测试和代码审查
  • 项目 2（Ngordnet）：设计、大规模实现
  • 项目 3（BYOW）：大规模设计

项目将有不同的评分器发布时间表和每个时间间隔内允许提交次数的限制。完整的评分器详细信息将在每个项目发布时提供。

项目 0、1、2 和 3 分别价值 50、50、125 和 125 分。

项目 3

由于 Project 3 是一个大规模设计项目，它将与其他三个项目有一些不同。

项目 3 将有一个同步检查部分。

考试评分

我们的考试目标是平均分为 65%。如果考试太难，班级平均分低于 65%，我们将对每个人的分数进行调整，使平均分达到 65%。

如果平均分达到或超过 65%，那么我们不会改变分数（即你的分数不会降低）。

考试的最高分为 100%。如果调整后你的分数超过 100%，在计算成绩时将上限设为 100%。

你不需要担心成绩调整的具体计算方式，但为了透明起见，我们在下面描述了计算方法：

为了计算调整后的分数，我们将每个人的分数乘以（0.65 / 平均分）。另一种数学上等效的表述方式是：我们将降低考试的最高分，直到平均分达到 65%。

示例：班级平均分为 60%，你的分数为 70%。调整后，你的分数将为 70 *（0.65 / 0.60）= 75.83%。

期末考试覆盖政策

对于那些错过考试、状态不佳或在整个学期取得重大进步的同学，考试覆盖政策让你有机会使用期末考试分数来弥补期中考试的一些分数。

覆盖政策仅在有助于提高你的分数时才会应用。例如，如果你在两次期中考试中都取得了中位数分数，但后来状态不佳，期末考试考得很差，我们不会改变你的期中考试分数。

覆盖政策只能用于弥补期中考试的分数。例如，如果你期中考试考得好，不能用来弥补期末考试的分数。

你不需要担心覆盖的具体计算方式，但为了透明起见，我们在下面描述了计算方法：

如果有助于提高你的成绩，我们将用你的期中考试和期末考试百分位分数的平均值来替换你的期中考试百分位分数。例如，如果你的期中考试 1 分数在第 50 百分位，期中考试 2 在第 30 百分位，期末考试在第 80 百分位，那么你覆盖后的期中考试 1 分数将在第 65 百分位，覆盖后的期中考试 2 分数将在第 55 百分位，而你的期末考试分数将保持在第 80 百分位。

学术不端

什么是作弊？ 学术不端的黄金法则是，你不应该声称对不属于你的工作负责。

这显然有一些解释空间，在整个课程中，你会从讲师、互联网、其他学生等那里得到一些帮助。这是可以的，我们希望课堂是一个开放、友好、协作的环境，我们可以互相帮助，尽可能高地理解课程材料。

为了帮助（但不完全定义）可接受行为的界限，我们对编程作业有三个重要规则：

  1. 独立完成 ：你提交的所有代码（骨架代码除外）都应该由你和你的搭档独立编写，除了解决小问题的小片段（示例见下面的允许部分）。

  2. 不得拥有或共享代码 ：在你提交最终作品之前，你永远不应该拥有你（或你的搭档）没有编写的解决方案代码。在网上查找解决方案代码实际上就是拥有解决方案代码。

    如果你将此类代码分发给其他学生或 61B 的未来学生（在合理范围内），你将承担同等责任。 不要把你的代码给任何人——即使他们在拼命请求。不要在网上发布解决方案（在 GitHub 或其他任何地方）！ 如果你不确定你做的事情是否可以，请询问。

  3. 引用来源 ：当你在编程作业中从他人那里获得重大帮助时，你应该在源代码的某个地方用注释中的 @source 标签引用该帮助。我们让你自己决定什么构成"重大"。但是，引用并不会改变允许的合作或参考程度。

    示例： 

    // @source 我与[某人]合作，下面的代码接收一个对象列表
// 并遍历列表，直到找到数字3并返回索引。
...

// @source 来自 https://stackoverflow.com/questions/16242733/sum-all-the-elements-java-arraylist，
// 下面的代码遍历列表并求和。
...

// @source 此代码由 ChatGPT 生成。它读取并解析文件中的所有整数，

...
