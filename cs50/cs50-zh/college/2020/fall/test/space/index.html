Complexities of Space

Not only can you use big-O notation to describe the “时间 complexity” (i.e., running 时间) of an algorithm, you can also use it to describe the “space complexity” of an algorithm: the amount of space that an algorithm requires based on the size, n, of its input, excluding the input itself.

For instance, whereas linear 搜索 might require O(n) 时间, it might only require O(1) space. Recall 第 3 周’s pseudocode:

For i from 0 to n-1
    If number behind i'th door
        Return true
Return false

Even though there were n doors, we only needed a constant amount of space, a variable called i, to help us iterate over those doors. The n doors themselves might take up O(n) space, but we exclude size of the algorithm’s input from analysis, else we’d need at least that much space no matter the algorithm!

To be fair, the number of bits we need to store i might technically depend on n. Indeed, the bigger n is, the 更多 bits we might need. But let’s not worry 关于 bits.

    Swap smallest item with i'th item

    Assuming its input is of size n, what’s the space complexity of 选择排序, using big-O notation? In no 更多 than three sentences, why?

    else

}

    In no 更多 than three sentences, why is the space complexity of this implementation of sum in C in O(n)? Assume no compiler optimizations.
