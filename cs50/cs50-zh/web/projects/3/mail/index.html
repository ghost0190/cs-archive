Mail

CS50W does not feature a one-to-one correspondence between 讲座 and 项目. If you are attempting this 项目 without having at least watched 讲座 5, you’re trying this too soon!

Design a front-end for an 电子邮件 client that makes API calls to send and receive emails.

入门

  1. 下载 the distribution code from https://cdn.cs50.net/web/2020/春季/项目/3/mail.zip and unzip it.
  2. In your terminal, cd into the mail directory.
  3. Run python manage.py makemigrations mail to make migrations for the mail app.
  4. Run python manage.py migrate to apply migrations to your database.

Understanding

In the distribution code is a Django 项目 called project3 that contains a single app called mail.

First, after making and applying migrations for the 项目, run python manage.py runserver to start the web server. 打开 the web server in your browser, and use the “Register” link to register for a new account. The emails you’ll be sending and receiving in this 项目 will be entirely stored in your database (they won’t actually be sent to real 电子邮件 servers), so you’re 欢迎 to choose any 电子邮件 address (e.g. foo@example.com) and password you’d like for this 项目: credentials need not be valid credentials for actual 电子邮件 addresses.

Once you’re signed in, you should see yourself taken to the Inbox page of the mail client, though this page is mostly blank (for now). Click the buttons to navigate to your Sent and Archived mailboxes, and notice how those, too, are currently blank. Click the “Compose” button, and you’ll be taken to a form that will let you compose a new 电子邮件. Each 时间 you click a button, though, you’re not being taken to a new route or making a new web request: instead, this entire application is just a single page, with JavaScript used to control the user interface. Let’s now take a closer look at the distribution code to see how that works.

Take a look at mail/urls.py and notice that the default route loads an index function in views.py. So let’s 打开 up views.py and look at the index function. Notice that, as long as the user is signed in, this function renders the mail/inbox.html template. Let’s look at that template, stored at mail/templates/mail/inbox.html. You’ll notice that in the body of the page, the user’s 电子邮件 address is first displayed in an h2 element. After that, the page has a sequence of buttons for navigating between various pages of the app. Below that, notice that this page has two main 小组课, each defined by a div element. The first (with an id of emails-view) contains the content of an 电子邮件 mailbox (initially empty). The second (with an id of compose-view) contains a form where the user can compose a new 电子邮件. The buttons along the top, then, need to selectively show and hide these views: the compose button, for 示例, should hide the emails-view and show the compose-view; the inbox button, meanwhile, should hide the compose-view and show the emails-view.

How do they do that? Notice at the bottom of inbox.html, the JavaScript file mail/inbox.js is included. 打开 that file, stored at mail/static/mail/inbox.js, and take a look. Notice that when the DOM content of the page has been loaded, we attach event listeners to each of the buttons. When the inbox button is clicked, for 示例, we call the load_mailbox function with the argument 'inbox'; when the compose button is clicked, meanwhile, we call the compose_email function. What do these functions do? The compose_email function first hides the emails-view (by setting its style.display property to none) and shows the compose-view (by setting its style.display property to block). After that, the function takes all of the form input fields (where the user might type in a recipient 电子邮件 address, subject line, and 电子邮件 body) and sets their value to the empty string '' to clear them out. This means that every 时间 you click the “Compose” button, you should be presented with a blank 电子邮件 form: you can test this by typing values into form, switching the view to the Inbox, and then switching 返回 to the Compose view.

Meanwhile, the load_mailbox function first shows the emails-view and hides the compose-view. The load_mailbox function also takes an argument, which will be the 姓名 of the mailbox that the user is trying to view. For this 项目, you’ll design an 电子邮件 client with three mailboxes: an inbox, a sent mailbox of all sent mail, and an archive of emails that were once in the inbox but have since been archived. The argument to load_mailbox, then, will be one of those three values, and the load_mailbox function displays the 姓名 of the selected mailbox by updating the innerHTML of the emails-view (after capitalizing the first character). This is why, when you choose a mailbox 姓名 in the browser, you see the 姓名 of that mailbox (capitalized) appear in the DOM: the load_mailbox function is updating the emails-view to include the appropriate text.

Of 课程, this application is incomplete. All of the mailboxes simply show the 姓名 of the mailbox (Inbox, Sent, Archive) but don’t actually show any emails yet. There’s no view yet to actually see the 目录 of any 电子邮件. And the compose form will let you type in the 目录 of an 电子邮件, but the button to send the 电子邮件 doesn’t actually do anything. That’s where you come in!

API

You’ll get mail, send mail, and update emails by using this application’s API. We’ve written the entire API for you (and documented it below), so that you can use it in your JavaScript code. (In fact, 笔记 that we have written all of the Python code for you for this 项目. You should be able to complete this 项目 by just writing HTML and JavaScript).

This application supports the following API routes:

GET /emails/<str:mailbox>

Sending a GET request to /emails/<mailbox> where <mailbox> is either inbox, sent, or archive will return 返回 to you (in JSON form) a list of all emails in that mailbox, in reverse chronological order. For 示例, if you send a GET request to /emails/inbox, you might get a JSON response like the below (representing two emails):

[
    {
        "id": 100,
        "sender": "foo@example.com",
        "recipients": ["bar@example.com"],
        "subject": "Hello!",
        "body": "Hello, world!",
        "timestamp": "Jan 2 2020, 12:00 AM",
        "read": false,
        "archived": false
    },
    {
        "id": 95,
        "sender": "baz@example.com",
        "recipients": ["bar@example.com"],
        "subject": "Meeting Tomorrow",
        "body": "What time are we meeting?",
        "timestamp": "Jan 1 2020, 12:00 AM",
        "read": true,
        "archived": false
    }
]

Notice that each 电子邮件 specifies its id (a unique identifier), a sender 电子邮件 address, an array of recipients, a string for subject, body, and timestamp, as well as two boolean values indicating whether the 电子邮件 has been read and whether the 电子邮件 has been archived.

How would you get access to such values in JavaScript? Recall that in JavaScript, you can use fetch to make a web request. Therefore, the following JavaScript code

fetch('/emails/inbox')
.then(response => response.json())
.then(emails => {
    // Print emails
    console.log(emails);

    // ... do something else with emails ...
});

would make a GET request to /emails/inbox, convert the resulting response into JSON, and then provide to you the array of emails inside of the variable emails. You can print that value out to the browser’s console using console.log (if you don’t have any emails in your inbox, this will be an empty array), or do something else with that array.

笔记 also that if you request an invalid mailbox (anything other than inbox, sent, or archive), you’ll instead get 返回 the JSON response {"error": "Invalid mailbox."}.

GET /emails/<int:email_id>

Sending a GET request to /emails/email_id where email_id is an integer id for an 电子邮件 will return a JSON representation of the 电子邮件, like the below:

{
        "id": 100,
        "sender": "foo@example.com",
        "recipients": ["bar@example.com"],
        "subject": "Hello!",
        "body": "Hello, world!",
        "timestamp": "Jan 2 2020, 12:00 AM",
        "read": false,
        "archived": false
}

笔记 that if the 电子邮件 doesn’t exist, or if the user does not have access to the 电子邮件, the route instead return a 404 Not Found error with a JSON response of {"error": "Email not found."}.

To get 电子邮件 number 100, for 示例, you might write JavaScript code like

fetch('/emails/100')
.then(response => response.json())
.then(email => {
    // Print email
    console.log(email);

    // ... do something else with email ...
});

POST /emails

So far, we’ve seen how to get emails: either all of the emails in a mailbox, or just a single 电子邮件. To send an 电子邮件, you can send a POST request to the /emails route. The route requires three pieces of data to be submitted: a recipients value (a comma-separated string of all users to send an 电子邮件 to), a subject string, and a body string. For 示例, you could write JavaScript code like

fetch('/emails', {
  method: 'POST',
  body: JSON.stringify({
      recipients: 'baz@example.com',
      subject: 'Meeting time',
      body: 'How about we meet tomorrow at 3pm?'
  })
})
.then(response => response.json())
.then(result => {
    // Print result
    console.log(result);
});

If the 电子邮件 is sent successfully, the route will respond with a 201 status code and a JSON response of {"message": "Email sent successfully."}.

笔记 that there must be at least one 电子邮件 recipient: if one isn’t provided, the route will instead respond with a 400 status code and a JSON response of {"error": "At least one recipient required."}. All recipients must also be valid users who have registered on this particular web application: if you try to send an 电子邮件 to baz@example.com but there is no user with that 电子邮件 address, you’ll get a JSON response of {"error": "User with email baz@example.com does not exist."}.

PUT /emails/<int:email_id>

The final route that you’ll need is the ability to mark an 电子邮件 as 阅读/unread or as archived/unarchived. To do so, send a PUT request (instead of a GET) request to /emails/<email_id> where email_id is the id of the 电子邮件 you’re trying to modify. For 示例, JavaScript code like

fetch('/emails/100', {
  method: 'PUT',
  body: JSON.stringify({
      archived: true
  })
})

would mark 电子邮件 number 100 as archived. The body of the PUT request could also be {archived: false} to unarchive the message, and likewise could be either {read: true} or read: false} to mark the 电子邮件 as 阅读 or unread, respectively.

Using these four API routes (getting all emails in a mailbox, getting a single 电子邮件, sending an 电子邮件, and updating an existing 电子邮件), you should have all the 工具 you now need to complete this 项目!

规格说明

Using JavaScript, HTML, and CSS, complete the implementation of your single-page-app 电子邮件 client inside of inbox.js (and not additional or other files; for grading purposes, we’re only going to be considering inbox.js!). You must fulfill the following requirements:

  • Send Mail: When a user submits the 电子邮件 composition form, add JavaScript code to actually send the 电子邮件.
    • You’ll likely want to make a POST request to /emails, passing in values for recipients, subject, and body.
    • Once the 电子邮件 has been sent, load the user’s sent mailbox.
  • Mailbox: When a user visits their Inbox, Sent mailbox, or Archive, load the appropriate mailbox.
    • You’ll likely want to make a GET request to /emails/<mailbox> to request the emails for a particular mailbox.
    • When a mailbox is visited, the application should first query the API for the latest emails in that mailbox.
    • When a mailbox is visited, the 姓名 of the mailbox should appear at the top of the page (this part is done for you).
    • Each 电子邮件 should then be rendered in its own box (e.g. as a <div> with a border) that displays who the 电子邮件 is from, what the subject line is, and the timestamp of the 电子邮件.
    • If the 电子邮件 is unread, it should appear with a white 背景. If the 电子邮件 has been 阅读, it should appear with a gray 背景.
  • View 电子邮件: When a user clicks on an 电子邮件, the user should be taken to a view where they see the content of that 电子邮件.
    • You’ll likely want to make a GET request to /emails/<email_id> to request the 电子邮件.
    • Your application should show the 电子邮件’s sender, recipients, subject, timestamp, and body.
    • You’ll likely want to add an additional div to inbox.html (in addition to emails-view and compose-view) for displaying the 电子邮件. Be sure to update your code to hide and show the right views when navigation options are clicked.
    • See the 提示 in the 提示 小组课 关于 how to add an event listener to an HTML element that you’ve added to the DOM.
    • Once the 电子邮件 has been clicked on, you should mark the 电子邮件 as 阅读. Recall that you can send a PUT request to /emails/<email_id> to update whether an 电子邮件 is 阅读 or not.
  • Archive and Unarchive: Allow users to archive and unarchive emails that they have received.
    • When viewing an Inbox 电子邮件, the user should be presented with a button that lets them archive the 电子邮件. When viewing an Archive 电子邮件, the user should be presented with a button that lets them unarchive the 电子邮件. This requirement does not apply to emails in the Sent mailbox.
    • Recall that you can send a PUT request to /emails/<email_id> to mark an 电子邮件 as archived or unarchived.
    • Once an 电子邮件 has been archived or unarchived, load the user’s inbox.
  • Reply: Allow users to reply to an 电子邮件.
    • When viewing an 电子邮件, the user should be presented with a “Reply” button that lets them reply to the 电子邮件.
    • When the user clicks the “Reply” button, they should be taken to the 电子邮件 composition form.
    • Pre-fill the composition form with the recipient field set to whoever sent the original 电子邮件.
    • Pre-fill the subject line. If the original 电子邮件 had a subject line of foo, the new subject line should be Re: foo. (If the subject line already begins with Re: , no need to add it again.)
    • Pre-fill the body of the 电子邮件 with a line like "On Jan 1 2020, 12:00 AM foo@example.com wrote:" followed by the original text of the 电子邮件.

提示

  • To create an HTML element and add an event handler to it, you can use JavaScript code like the below:
const element = document.createElement('div');
element.innerHTML = 'This is the content of the div.';
element.addEventListener('click', function() {
    console.log('This element has been clicked!')
});
document.querySelector('#container').append(element);

This code creates a new div element, sets its innerHTML, adds an event handler to run a particular function when that div is clicked on, and then adds it to an HTML element whose id is container (this code assumes that there is a HTML element whose id is container: you’ll likely want to change the argument to querySelector to be whichever element you’d like to add an element to).

  • You 五月 find it helpful to edit mail/static/mail/styles.css to add any CSS you need for the application.
  • Recall that if you have a JavaScript array, you can loop over each element of that array using forEach.
  • Recall that normally, for POST and PUT requests, Django requires a CSRF token to guard against potential cross-site request forgery attacks. For this 项目, we’ve intentionally made the API routes CSRF-exempt, so you won’t need a token. In a real-世界 项目, though, always best to guard against such potential vulnerabilities!
