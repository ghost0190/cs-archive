实验：文件系统

在本实验中，你将为 xv6 文件系统添加大文件和符号链接。

在编写代码之前，你应该阅读xv6手册中的"第8章：文件系统"并研究相应的代码。

获取实验的 xv6 源代码并切换到 util 分支： 

  $ git fetch
  $ git checkout fs
  $ make clean

大文件

在本作业中，你将增加 xv6 文件的最大大小。目前 xv6 文件限制为 268 个块，或 268*BSIZE 字节（在 xv6 中 BSIZE 为 1024）。这个限制来自于 xv6 inode 包含 12 个"直接"块号和一个"单次间接"块号的事实，后者引用一个最多容纳 256 个块号的块，总共 12+256=268 个块。

bigfile 命令创建它能创建的最长文件，并报告该大小： 

$ bigfile
..
wrote 268 blocks
bigfile: file is too small
$
测试失败是因为 bigfile 期望能够创建一个有 65803 个块的文件，但未修改的 xv6 将文件限制为 268 个块。

你将修改 xv6 文件系统代码以支持每个 inode 中的"双重间接"块，包含 256 个单次间接块的地址，每个地址又可以包含最多 256 个数据块的地址。结果是文件将能够由最多 65803 个块组成，或 256*256+256+11 个块（11 而不是 12，因为我们将牺牲一个直接块号用于双重间接块）。

预备知识

mkfs 程序创建 xv6 文件系统磁盘映像并确定文件系统的总块数；这个大小由 kernel/param.h 中的 FSSIZE 控制。 你会看到本实验仓库中的 FSSIZE 设置为 200,000 个块。你应该在 make 输出中看到 mkfs/mkfs 的以下输出： 
nmeta 70 (boot, super, log blocks 30 inode blocks 13, bitmap blocks 25) blocks 199930 total 200000
这一行描述了 mkfs/mkfs 构建的文件系统：它有 70 个元数据块（用于描述文件系统的块）和 199,930 个数据块，总共 200,000 个块。
如果在实验过程中你发现需要从重建文件系统开始，你可以运行 make clean，这会强制 make 重建 fs.img。

需要关注的内容

磁盘上 inode 的格式由 fs.h 中的 struct dinode 定义。你特别需要关注 NDIRECT、NINDIRECT、MAXFILE 以及 struct dinode 的 addrs[] 元素。请查看 xv6 文本中的图 8.3 以获取标准 xv6 inode 的图示。

在磁盘上查找文件数据的代码在 fs.c 中的 bmap() 中。请查看它并确保你理解它在做什么。bmap() 在读取和写入文件时都会被调用。写入时，bmap() 根据需要分配新块来保存文件内容，以及分配间接块来保存块地址（如果需要的话）。

bmap() 处理两种块号。bn 参数是"逻辑块号"——文件内的块号，相对于文件的起始位置。ip->addrs[] 中的块号和 bread() 的参数是磁盘块号。你可以将 bmap() 视为将文件的逻辑块号映射到磁盘块号。

你的任务

修改 bmap() 使其实现双重间接块，除了直接块和单次间接块之外。你只需要有 11 个直接块，而不是 12 个，以便为你的新双重间接块腾出空间；你不允许更改磁盘上 inode 的大小。ip->addrs[] 的前 11 个元素应该是直接块；第 12 个应该是单次间接块（就像当前的）；第 13 个应该是你的新双重间接块。当 bigfile 写入 65803 个块且 usertests 成功运行时，你就完成了本练习： 
$ bigfile
..................................................................................................................................................................................................................................................................................................................................................................................................................................................................................................................................................................................................................................................................................
wrote 65803 blocks
done; ok
$ usertests
...
ALL TESTS PASSED
$

bigfile 至少需要一分半钟来运行。

提示：

  • 确保你理解 bmap()。画出 ip->addrs[]、间接块、双重间接块及其指向的单次间接块和数据块之间关系的图示。确保你理解为什么添加双重间接块会将最大文件大小增加 256*256 个块（实际上是 -1，因为你必须将直接块数减少一个）。
  • 考虑如何使用逻辑块号来索引双重间接块及其指向的间接块。
  • 如果你更改了 NDIRECT 的定义，你可能还需要更改 file.h 中 struct inode 的 addrs[] 声明。确保 struct inode 和 struct dinode 的 addrs[] 数组具有相同数量的元素。
  • 如果你更改了 NDIRECT 的定义，确保创建一个新的 fs.img，因为 mkfs 使用 NDIRECT 来构建文件系统。
  • 如果你的文件系统进入错误状态，可能是由于崩溃，删除 fs.img（从 Unix 执行此操作，而不是 xv6）。make 将为你构建一个新的干净文件系统映像。
  • 不要忘记 brelse() 你 bread() 的每个块。
  • 你应该只在需要时分配间接块和双重间接块，就像原始的 bmap() 一样。
  • 确保 itrunc 释放文件的所有块，包括双重间接块。

符号链接

在本练习中，你将为 xv6 添加符号链接。符号链接（或软链接）通过路径名引用一个链接文件；当打开符号链接时，内核跟随链接到被引用的文件。符号链接类似于硬链接，但硬链接被限制为指向同一磁盘上的文件，而符号链接可以跨越磁盘设备。虽然 xv6 不支持多个设备，但实现这个系统调用是理解路径名查找如何工作的一个很好的练习。

你的任务

你将实现 symlink(char *target, char *path) 系统调用，它在 path 处创建一个新的符号链接，引用 target 命名的文件。更多信息请参见 man page symlink。要测试，将 symlinktest 添加到 Makefile 并运行它。当测试产生以下输出（包括 usertests 成功）时，你的解决方案就完成了。 

$ symlinktest
Start: test symlinks
test symlinks: ok
Start: test concurrent symlinks
test concurrent symlinks: ok
$ usertests
...
ALL TESTS PASSED
$

提示：

  • 首先，为 symlink 创建一个新的系统调用号，在 user/usys.pl 和 user/user.h 中添加一个条目，并在 kernel/sysfile.c 中实现一个空的 sys_symlink。
  • 在 kernel/stat.h 中添加一个新的文件类型（T_SYMLINK）来表示符号链接。
  • 在 kernel/fcntl.h 中添加一个新标志（O_NOFOLLOW），可以与 open 系统调用一起使用。注意，传递给 open 的标志使用按位或运算符组合，所以你的新标志不应与任何现有标志重叠。这将使你在将 user/symlinktest.c 添加到 Makefile 后能够编译它。
  • 实现 symlink(target, path) 系统调用，在 path 处创建一个引用 target 的新符号链接。注意，target 不需要存在就能使系统调用成功。你需要选择某个地方来存储符号链接的目标路径，例如 inode 的数据块中。symlink 应返回一个表示成功（0）或失败（-1）的整数，类似于 link 和 unlink。
  • 修改 open 系统调用以处理路径引用符号链接的情况。如果文件不存在，open 必须失败。当进程在 open 的标志中指定 O_NOFOLLOW 时，open 应该打开符号链接本身（而不跟随符号链接）。
  • 如果被链接的文件也是符号链接，你必须递归跟随它，直到到达一个非链接文件。如果链接形成循环，你必须返回一个错误代码。你可以通过在链接深度达到某个阈值（例如10）时返回错误代码来近似实现。
  • 其他系统调用（例如 link 和 unlink）不得跟随符号链接；这些系统调用直接操作符号链接本身。
  • 你不必在本实验中处理指向目录的符号链接。
