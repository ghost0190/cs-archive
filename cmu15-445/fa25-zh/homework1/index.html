概述

第一个作业是构建一组 SQL 查询来分析将提供给您的数据集。为此，您将研究 Lahman Database。本次作业是一次很好的机会来：(1) 学习基本和某些高级 SQL 特性，(2) 熟悉使用功能完备的数据库管理系统 DuckDB，它在未来可能对您可能有所帮助。

这是一个个人项目，需要独立完成（即不分组）。

  • 发布日期： Aug 27, 2025
  • 截止日期： Sep 07, 2025 @ 11:59pm

规格说明

本次作业共包含 6 道题目，满分 100 分。每道题都需要构建一个 SQL 查询来获取所需数据。每道题的答案应只包含一条语句。完成这些题目大约需要 6 小时。

占位文件夹

创建提交用的占位文件夹，并为每道题创建空的 SQL 文件：

$ mkdir placeholder
$ cd placeholder
$ touch q1_sample.duckdb.sql \
        q2_hr.duckdb.sql \
        q3_mvp.duckdb.sql \
        q4_award.duckdb.sql \
        q5_hof.duckdb.sql \
        q6_upsert.duckdb.sql

填写完查询后，您可以运行以下命令来压缩文件夹：

$ zip -j submission.zip placeholder/*.sql

-j 参数可以让您将所有 SQL 查询压缩到 zip 文件中而不包含路径信息。如果不这样做，评分脚本将无法正常工作。

构建 SQL 查询

现在开始构建 SQL 查询并将它们放入占位文件中。您可以先使用 SQLite。

Q1 [0 分]

此查询的目的是确保您的输出格式与我们的自动评分脚本的输出格式完全匹配。

文件： q1_sample.duckdb.sql

详情： 按字母顺序列出所有活跃的分区。

答案：以下是正确的 SQL 查询和预期输出： 

D SELECT DISTINCT division FROM divisions WHERE active = 'Y' ORDER BY division;
AL Central
AL East
AL West
NL Central
NL East
NL West

您应该将此 SQL 查询放入提交目录（placeholder）中的相应文件（q1_sample.duckdb.sql）中。

Q2 [20 分]

找出在任何单次出场中本垒打（HR）最高的十个人，不考虑年份或球队。只考虑曾经在 PA 的学校打过球的人。按本垒打数从多到少排序，然后按名字字母顺序排列。

文件： q2_hr.duckdb.sql

提示： || 可能对构造名称字段很有用。名称应按 {FIRST} ({GIVEN}) {LAST} 的格式组装。球员在任何单次出场中的最高本垒打数可以通过对给定球员的 appearances 中所有年份和球队进行聚合来找到。

您的输出应如下所示： 

name|max_hr_appearance

您的第一行应如下所示： 

Bobby (Robert Leigh) Higginson|30

Q3 [20 分]

找出十对（球员，球队），其中球员在 1999 年之后在活跃联盟中赢得了 Gold Glove 奖项，并且打击出场的比赛场次多于该球队自 1999 年以来的平均打击出场数。按不同获奖年份从多到少排序，然后按 given name 字母顺序排列。

文件： q3_mvp.duckdb.sql

提示： 只考虑 awardID 匹配 Gold Glove 的记录。球队平均值可以通过对自 1999 年以来每个球队球员的 appearances 中的打击出场数取平均来计算。您可能会发现 DuckDB 中的相关子查询很有用。

您的输出应如下所示： 

nameGiven|teamID|distinct_years

您的第一行应如下所示： 

Ichiro|SEA|10

Q4 [30 分]

考虑事件 E：对于给定的（球队，年份），球队有超过 5 名不同球员获得奖项，且某位经理在同一年获得了奖项。对于所有活跃联盟，找出事件 E 发生过超过一次的球队。按事件 E 发生次数从多到少排序，然后按球队名称字母顺序排列。

文件： q4_award.duckdb.sql

提示： 您可能会发现 DuckDB 中的相关子查询和 CTE 很有用。考虑将问题分解为子问题并组合它们的结果。

您的输出应如下所示： 

league|team_name|distinct_years

输出中的一行如下所示： 

National League|Atlanta Braves|3

Q5 [20 分]

找出 10 位入选名人堂的球员。对于每位入选的球员，找出他们曾一起出场的最早队友。如果有多位队友，选择按队友构造名称字母顺序排列的第一位队友。按名人堂球员的构造名称字母顺序排列。

文件： q5_hof.duckdb.sql

详情： 要找到球员的队友，找出两人都作为 appearances 在同一年的同一支球队效力的记录。

提示： 您可能会发现 DuckDB 中的Lateral Joins很有用。所有名称应按 {FIRST} ({GIVEN}) {LAST} 的格式组装。

您的输出应如下所示： 

hof_player_name|earliest_teammate_name|earliest_teammate_year

您的第一行应如下所示： 

Addie (Adrian) Joss|Bill (William Henry) Bernhard|1902

Q6 [10 分]

联盟总监要求您向 teams 表中插入新记录。对于 2024 年的所有球队，使用 franchID 作为 teamID 插入一条新记录。如果插入因冲突而失败，将现有记录的 attendance 设置为 -1。

文件： q6_upsert.duckdb.sql

详情： 我们将通过选择表中 2024 年的所有球队并按每列依次排序来进行评估。 

SELECT yearID, lgID, teamID, franchID, teamRank, attendance
FROM teams
WHERE yearID = 2024
ORDER BY lgID, teamID, franchID, teamRank, attendance;

提示 考虑如何在一条语句中同时插入和更新现有行。

运行选择语句后，应存在以下两行： 

2024|AL|HOU|HOU|1|-1
2024|AL|KCA|KCR|2|1658347

评分标准

每份提交将根据 SQL 查询是否从数据库中获取了预期的元组集合来评分。每个 SQL 查询只允许一条语句。请注意，您的 SQL 查询将通过将其输出（即元组集合）与正确输出进行比较来进行自动评分。对于您的查询，输出列的顺序很重要；列名则不重要。
